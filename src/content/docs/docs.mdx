## Protocol compatibility

MCP Failure Lab uses MCP TypeScript SDK v2 and targets protocol version
`2026-07-28` by default for built-in scenario execution. Scenarios can select `2025-11-25`
with `protocolVersion`. The stdio and Streamable HTTP
servers also accept `2025-11-25` clients for compatibility.

The health, delay, hang, disconnect, and response fault tools support both protocol eras.
`session_loss` is limited to initialized legacy HTTP sessions, while
`response_after_cancellation` is limited to stdio. The current working-tree
`protocol_ping_liveness` tool sends a server-to-client protocol ping on `2025-11-25`;
it reports `unsupported` on `2026-07-28`. See [Fault Tools](/docs/fault-tools/) for availability
and transport behavior.

See [External compatibility](/docs/compatibility/) for the versioned client matrix and known
transport-specific behavior.

:::note[Current scope]
Failure Lab runs scenarios against its built-in server or a configured external HTTP or stdio MCP
target. The built-in server provides malformed and duplicate JSON-RPC response faults.
Session-loss testing is available for initialized legacy HTTP sessions.
:::
